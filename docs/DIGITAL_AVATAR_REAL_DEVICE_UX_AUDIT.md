# Digital Avatar 真机体验专项审计

日期：2026-08-25

## 证据来源

本审计基于用户提供的真机截图与当前代码链路。截图显示数字人格已经进入问答页，状态为字幕模式；本地尚未取得可复核的微信开发者工具 Console 或真机日志，因此不把截图之外的运行结果当作已验证事实。

## 发现的问题

### P0 · Character Router 主题错配

截图中的回答内容是手抓羊肉、八宝茶、羊肉臊子面等美食主题，但角色显示为岩羊。根因是 `digital-avatar-service.prepare()` 在没有新协议 `character` 时优先读取旧 `result.agent.id`；旧 Agent 的 FOOD 路由可能返回 `rock-goat`，从而覆盖了基于用户问题的角色判断。

修复原则：新协议角色 > 明确 canonical 角色；否则以 Intent/Topic/Entity/Knowledge Focus 重新路由，不能盲信旧 legacy agent。

### P1 · 信息架构文案错位

页面显示“或直接问萌宠”，下方却是西夏陵、贺兰山岩画、贺兰山国家森林公园等景区话题。应改为“想从哪里开始？”，避免把景区快捷卡误称为角色选择。

### P1 · 数字人格视觉主次不清

角色图尺寸偏小，像头像而非数字人格主视觉；完整答案、口播稿、状态提示和操作按钮连续堆叠，首屏缺少明确主角。

### P1 · Toast 遮挡

字幕模式使用长文本 Toast，可能遮挡角色名称和身份信息。字幕模式应是正常产品状态，改为卡片内状态 chip。

### P1 · 口播稿开发感较强

“口播稿：”标签和整段长文本像调试信息。应改为“角色正在讲”，单独展示精简口播内容，完整回答折叠在后续可信信息区域。

### P2 · 操作状态不够明确

停止按钮长期显示，开始/播放中/结束状态不够清晰。应根据 `IDLE / SPEAKING / HAPPY` 动态显示开始讲解、停止讲解、再听一次。

## 本阶段修复范围

- 修复四层角色路由与旧 Agent 兼容优先级。
- 增加角色路由自动化测试。
- 调整快捷问题标题。
- 放大角色主视觉并保持 `aspectFit`。
- 将字幕模式改为卡片内状态，不再用长 Toast。
- 优化口播字幕和按钮状态。

不改首页架构、不新增模型、不引入新页面、不修改原创 IP 素材。
