### 1. AI 导出文件缺少强制标准要求的隐式元数据标识

本轮已补齐页面显式标识和相册导出像素标识，但 Canvas 导出的 JPEG 尚未按强制标准写入包含生成合成属性、服务提供者编码、内容编号等字段的隐式元数据。图片供应端或专门的服务端后处理必须完成隐式标识；微信提审资料和用户协议也必须说明标识方法。

依据：《人工智能生成合成内容标识办法》第 4–8 条要求图片显式标识、导出文件保留显式标识、文件元数据隐式标识，以及应用上线时提交相关说明。该办法自 2025-09-01 起施行：<https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm>

### 2. 分布式高并发控制尚未完成

当前实现只具备页面防重复点击、单实例生图并发闸门、同实例请求合并、超时和本地知识库降级。云函数横向扩容后，不同实例之间仍会重复执行；本地每日 20 次只是前端提示，可被绕过；文本模型仍由客户端 CloudBase SDK 直接调用，缺少统一服务端配额、租户隔离和全局熔断。

上线前必须补齐：

- 以服务端可信用户/设备标识为键的全局令牌桶；
- 持久化幂等表（`requestId + operation + subject` 唯一键、状态机、TTL、结果摘要）；
- 仅对明确可重试的 429/5xx/网络错误做指数退避和抖动，生成任务超时未知时不得盲目重放；
- 生图进入队列并设置账户级并发、日预算、单用户配额与熔断；
- 文本 AI 统一经服务端网关，限制输入/输出长度、并发、超时和成本；
- 数据库、云存储和云函数分别配置最小权限及容量告警。

项目方已确认正式后端采用微信云托管。推荐把文本 AI、生图、内容审核、配额和幂等统一收口到一个云托管 API 网关：小程序只携带登录态和请求 ID；服务端取得可信用户身份，以 Redis/数据库实现分布式限流和幂等状态机，再调用模型服务。云托管支持弹性部署，但弹性扩容本身不等于业务幂等或成本保护，以上控制仍需应用实现。腾讯云官方说明：<https://cloud.tencent.com/document/product/876/113602>

### 3. 内容安全和投诉闭环不足

客户端关键词过滤不是内容安全系统。正式服务需要输入审核、输出审核、图片审核、风险分级、违规处置、申诉/投诉入口、处理时限和审计记录；还需明确未成年人适用范围。当前个人中心反馈仅保存在本机，运营方收不到，不能作为有效投诉机制。

依据：《生成式人工智能服务管理暂行办法》第 9–15 条涉及个人信息、服务稳定性、违法内容处置和投诉举报机制：<https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm>

### 4. 微信与云平台状态无法由代码证明

必须由管理员在微信公众平台和 CloudBase 控制台核验：主体认证、备案、名称与简介、服务类目、隐私保护指引、AI 生成合成服务声明、合法域名、云函数部署版本、环境变量、数据库/存储权限、日志留存、内容安全能力、体验版、审核和发布。

本机已发现微信开发者工具，但当前受限环境不能读取其登录态，因此本轮没有形成“开发者工具真实编译/预览成功”的证据；不得用 Node 语法检查替代微信编译结果。
