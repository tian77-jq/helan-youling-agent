# 首页空白运行时根因与验收日志

日期：2026-08-23
构建：`20260823-home-static-render-18`

## 用户现场证据

- App 与首页生命周期均执行成功。
- 首页数据完成挂载，景区图片进入 `bindload`。
- 相同景区出现重复 LOAD，随后基础库服务上下文报告 `Error: timeout`。

## 根因判断

页面数据与 WXML 节点并未缺失。自动化读取到旧首页根节点高 3836px，标题、输入框和入口均为可见状态；截图也能正常绘制。因此空白不是业务 JS 未注册，而是复杂首页在部分开发者工具/设备上的渲染层超时。

旧首页同时包含 3 个原生 `swiper`。其中 `circular` 会为循环显示创建额外视图，景区数据又同时进入大图轮播和精选列表，导致同一图片重复加载。多次延迟 `setData` 继续扩大视图差量，和用户日志中“重复图片 LOAD 后 timeout”的顺序一致。

## 修复

- 首页原生 `swiper`：3 → 0。
- 首页 `autoplay`：1 → 0。
- 景区首次节点：6 个轮播项 + 3 个重复精选项 → 4 个唯一静态项。
- 非遗首屏：4 → 2 个静态延迟图片卡。
- 美食首屏：4 → 2 个静态延迟图片卡。
- 分阶段视图更新：4 次 → 1 次紧凑更新。
- 删除全部无引用轮播状态、事件函数和 WXSS。
- 更新构建标识，防止继续误测旧缓存。
