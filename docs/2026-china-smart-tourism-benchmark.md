# 国内智慧文旅对标（2026-08）

本报告用于产品决策，不是功能照抄清单。公开资料中的功能属于“资料事实”；“对《贺兰有灵》的启发”属于设计推断。案例资料以官方机构、景区或腾讯合作发布为主。

| 案例 | 公开资料事实 | 对《贺兰有灵》的启发 | 不复制 |
|---|---|---|---|
| 一部手机游云南 | 覆盖游前、游中、游后，含预约、导览、AI识景、厕所/车位、投诉等全流程服务。[1][2] | 设计“行前—在途—行后”服务闭环，先做高频任务。 | 不做省级全域平台规模 |
| 智游龙门石窟 | 有手绘地图、主题路线、AI导游、语音讲解、设施查找和文化小游戏。[3] | 宁夏应把三萌宠绑定到知识、路线和具体点位。 | 不复制龙门素材/IP |
| 云游敦煌 | 支持按艺术形式、朝代和主题探索，并延伸到数字藏经洞。[4][5] | 将西夏、丝路、黄河做成可探索的文化线索。 | 不把文化压缩成静态百科卡 |
| 智游黄山 | 提供电子导览、AR、实景直播、客流与路线等服务。[6][7] | 预留实时状态层，缺数据时显示“待核验”。 | 不伪造实时天气、客流或开放信息 |
| 数字故宫 | 有预约购票、线路导航、官方讲解、AR、舒适度和定制路线。[8] | Trip 应展示时间槽、路线依据和可调整入口。 | 不引入无授权文物内容 |
| 武隆喀斯特小程序 | 官方名录公开景区、预约渠道、门票和开放时段等信息。[9] | 景点实体必须有来源、更新时间和实时门控。 | 不把静态价格当实时价格 |
| 首钢园智慧体验 | 腾讯案例包含小程序智慧导览、停车、订票和消费。[10] | 把“到达后的服务”列为二期，而非只做聊天。 | 不提前做伪支付 |
| 智游中山 | 广东官方培育项目名单列出“智游中山”微信小程序。[11] | 关注城市级内容组织与统一入口。 | 不因案例入选就推断具体功能 |
| 智慧世博馆 | 上海官方资料提到无障碍导览、定位导航等场馆体验。[12] | QA、字幕和无障碍交互应是一等能力。 | 不把AR当必需炫技 |
| 游云南扫景点 | 官方资料提到扫码进入景点图集、语音讲解和城市地图检索。[13] | 用扫码/点位触发“问这处”与知识讲解。 | 不复用第三方图片或文案 |

## 共同结论

1. 领先产品的核心不是聊天框，而是“内容资产 + 场景服务 + 路线/位置 + 互动”。
2. AI 应服从任务契约和知识证据；程序决定任务，模型负责表达。
3. 实时信息必须有独立状态：`VERIFIED`、`STALE`、`UNAVAILABLE`，不可用时明确提示官方渠道。
4. 《贺兰有灵》的差异化应是“宁夏文化知识 + 三萌宠人格 + 可执行行程 + AI共创”，而不是复制综合OTA。
