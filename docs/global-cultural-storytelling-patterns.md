# 全球文化叙事模式拆解

## 模式一：遗产不是资料页，而是问题入口

敦煌数字案例、龙门石窟数字案例和 UNESCO 遗产解释框架共同指向一个模式：用户先被一个可回答的问题吸引，再沿对象、地点和证据深入。项目落地为 `hook → narrative → facts → action`，而不是把百科字段直接倾倒给用户。

## 模式二：地点是故事的锚，行动是故事的出口

NPS App 与园区导览类产品把地图、活动和解释放在同一体验中。项目因此要求每个 `story` 同时具有 `location`、`relatedPlaces`、`interaction` 和 `action`，并让 Trip 使用这些地点继续规划。

## 模式三：角色差异要改变叙事视角

角色统一不是换头像，而是限制角色能讲什么、用什么语气、把用户带向什么动作。岩羊不负责路线客服，骆驼不替代生态解释，沙狐不把夜游说成没有约束的灯光清单。

## 模式四：社区与承载边界必须进入故事

UNESCO 相关指南强调利益相关者、影响和持续管理。非遗故事使用“谁在做—怎么做—我能如何支持”的行动卡；生态和夜游故事使用低扰动、安全、开放时间与返程边界。

## 模式五：创作是理解之后的再表达

AI Create 接收故事标题、主题、视觉符号和地点，再生成创作提示；提示明确避免凭空添加未核验史实。这样“生成一张图”变成“把理解转译成作品”。

## 取舍结论

本项目不追求一次实现所有沉浸式技术，而优先完成四个可演示闭环：故事卡打开、角色讲解、地点进入 Trip、故事进入 AI Create。它们能在小程序内形成可复查的叙事链路，也能为后续真实音频、地图和线下合作留下接口。
